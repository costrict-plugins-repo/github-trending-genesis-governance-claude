# Privacy Policy for Genesis Governance

**Effective date:** April 17, 2026

Genesis Governance is a plugin for Claude Code that helps users establish a governance framework for software projects. This Privacy Policy explains what data the plugin may process, how that data is handled, and what Genesis Governance does and does not collect.

## 1. Scope

This Privacy Policy applies to the Genesis Governance plugin and its related commands, including `/genesis-governance` and `/genesis-sync`.

It applies only to the plugin itself. It does not govern Anthropic’s services, Claude Code, GitHub, or any third-party tools or platforms used alongside the plugin. Those services are governed by their own terms and privacy policies.

## 2. What the plugin does

Genesis Governance analyzes project context and repository artifacts in order to generate governance-related files, such as:

- governance configuration
- project constitution and documentation artifacts
- `CLAUDE.md`
- document registry files
- CI configuration
- audit artifacts
- project-specific agent definitions

The plugin is designed to operate within the user’s Claude Code workflow and repository context.

## 3. Data the plugin may process

Depending on how the user invokes the plugin, Genesis Governance may process:

- repository files and folder structure
- configuration files
- documentation files
- project metadata
- user-provided prompts and answers during the intake flow
- governance artifacts generated during plugin execution

This processing is limited to what is necessary to generate, update, validate, or audit the governance artifacts requested by the user.

## 4. Data collection and transmission

Genesis Governance does **not** collect, sell, rent, or monetize user personal data.

Genesis Governance does **not**, by default, transmit repository contents, prompts, or project documents to developer-operated external servers.

If the user’s environment, platform, or surrounding tooling sends data to third-party providers, that behavior is outside the direct control of Genesis Governance and is governed by the applicable third-party service policies.

## 5. Storage and retention

Genesis Governance does not maintain a separate developer-controlled remote database of user project data.

Any files created or modified by the plugin are stored in the user’s own project or working environment, according to the user’s repository, local environment, and platform settings.

Examples may include:

- `docs/intake/genesis-checkpoint.json`
- governance documentation files
- CI workflow files
- generated agent files
- audit and registry artifacts

Retention of those files is controlled by the user and their own storage, version control, and repository practices.

## 6. Analytics and telemetry

Genesis Governance does **not** use developer-operated analytics, advertising trackers, or behavioral profiling by default.

If this changes in the future, this Privacy Policy will be updated accordingly.

## 7. Third-party services

Genesis Governance may operate within environments that themselves involve third-party services, such as:

- Anthropic / Claude Code
- GitHub
- local development environments
- CI providers

Genesis Governance does not control how those services collect, store, or process data. Users should review the privacy policies of those providers separately.

## 8. Security

Genesis Governance is designed to work within the user’s existing development environment and repository boundaries.

However, no software tool can guarantee absolute security. Users are responsible for:

- reviewing generated output before committing or deploying it
- controlling repository permissions
- protecting secrets, credentials, and sensitive files
- using secure development and CI practices

Users should not rely on the plugin as a substitute for legal, compliance, security, or privacy review where those reviews are required.

## 9. Sensitive information

Users should avoid including unnecessary personal data, secrets, regulated information, or highly sensitive material in prompts or project files unless their own environment and governance processes are appropriate for handling such data.

Genesis Governance is a project governance tool, not a regulated data processing or secure records management system.

## 10. Children’s privacy

Genesis Governance is not directed to children and is not intended for use by individuals under the age required to use the surrounding development tools and platforms.

## 11. International use

Users may access or use Genesis Governance from different jurisdictions. The plugin itself is intended as a development tool, and users are responsible for evaluating whether their use complies with applicable local laws, regulations, and internal policies.

## 12. Changes to this Privacy Policy

This Privacy Policy may be updated from time to time to reflect changes in the plugin’s functionality or data handling practices.

If material changes are made, the updated version will be published with a revised effective date.
